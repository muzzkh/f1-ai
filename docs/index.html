The project

This page is a snapshot. The full project runs on your own machine, for any session, with no API keys.

Dashboard

A Streamlit app with six views over any session since 2023: race, pace and tyres, telemetry, video lab, championship. Everything on this page comes from it.

MCP server

13 tools that let an AI assistant such as Claude answer F1 questions with real numbers instead of guessing.

Data analysis

Clean-lap pace, a fuel-corrected tyre model, measured pit loss, strategy ranking and GPS-aligned lap comparison.

Video to telemetry

Turns an onboard video's HUD into a telemetry CSV, with a renderer that makes test footage to measure accuracy against.

Run it

git clone https://github.com/muzzkh/f1-ai.git
cd f1-ai
python -m venv .venv
.venv/Scripts/python -m pip install -e .        # macOS / Linux: .venv/bin/python
.venv/Scripts/python -m streamlit run dashboard/app.py

MCP tools

ToolWhat it does
get_scheduleRace calendar for a season: round numbers, event names, dates, which sessions each weekend has, and whether it has already been run.
get_standingsCurrent (or final) driver and constructor championship standings for a season.
get_session_resultsClassification of a session. Races: position, grid, gap to winner, status, points. Qualifying: Q1/Q2/Q3 times. Also weather and each driver's best lap.
get_lap_timesEvery lap of one driver: lap time, sectors, tyre compound and age, position, pit in/out flags and track status (GREEN / SC / VSC / RED).
get_race_paceDrivers ranked by representative pace: median of clean laps (green flag, no pit laps, within 107% of the fastest), with gap to the quickest.
get_tyre_strategyWhat each driver ran: every stint with compound, lap range, tyre age at the start and median clean pace.
get_tyre_degradationFitted race pace model: how much slower each dry compound gets per lap of age, pace offset between compounds, the fuel-burn effect, each driver's underlying pace, plus measured pit-stop time loss. A simple linear model; treat the numbers as estimates and check r2.
simulate_race_strategyRank dry-tyre pit strategies for a race by predicted total time using the fitted degradation model and measured pit loss, and show what the winner actually did. Ignores traffic, safety cars and track evolution.
compare_driversHead-to-head telemetry comparison of two laps (each driver's fastest unless lap numbers are given): lap summaries, minimum speed and time gained at every corner, and time gained in each of 25 slices of the lap. Positive gain_a values mean driver A was faster there. Corner-level numbers are indicative (about +/-0.05 s).
get_lap_telemetryTelemetry trace of one lap (fastest if no lap number), resampled to `points` evenly spaced distances: speed, throttle, brake, gear, RPM, DRS.
list_hud_profilesHUD layout profiles available for video-to-telemetry extraction.
render_onboard_videoRender a lap's real telemetry as an onboard-style video with a HUD overlay (speed, gear, throttle, brake, RPM). Useful as test footage with known ground truth for video_to_telemetry. Returns the file path.
video_to_telemetryRead telemetry (speed, gear, throttle, brake, RPM, DRS) out of an onboard video by analysing its HUD graphics, and save it as CSV. `profile` names the HUD layout (see list_hud_profiles); footage with a different HUD needs its own calibrated profile. If a reference lap is given the result is time-aligned to the official telemetry and its accuracy reported. Check speed_read_rate_pct: a low value means the profile does not fit.

Timing data from OpenF1, corner positions from MultiViewer, standings from Jolpica. Charts are interactive: hover for values, drag to zoom, double-click to reset.
